Contexte & Objectifs

Une université souhaite mettre en place un système numérique permettant de publier et vérifier l'authenticité des diplômes. Les fichiers PDF ne sont pas stockés sur la blockchain : seule leur empreinte cryptographique (hash) y est enregistrée.

Objectifs du TP :
  • Émettre un diplôme (réservé à l'administrateur)
  • Vérifier l'authenticité d'un diplôme via son hash
  • Révoquer un diplôme
  • Bloquer les utilisateurs non autorisés

Smart Contract Complet — DiplomaRegistry.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract DiplomaRegistry {

    // ============================================================
    //  ÉTAT DU CONTRAT
    // ============================================================

    address public owner;
    uint public diplomaCount;

    struct Diploma {
        string  studentName;   // Nom de l'étudiant
        bytes32 diplomaHash;   // Hash du PDF
        uint    issuedAt;      // Timestamp d'émission
        bool    revoked;       // Statut de révocation
    }

    mapping(uint => Diploma) private diplomas;
    mapping(bytes32 => bool) private hashUsed;   // Bonus 2

    // ============================================================
    //  ÉVÉNEMENTS
    // ============================================================

    event DiplomaIssued(
        uint indexed diplomaId,
        string studentName,
        bytes32 diplomaHash,
        uint issuedAt
    );

    event DiplomaRevoked(
        uint indexed diplomaId,
        string studentName,
        uint revokedAt
    );

    // ============================================================
    //  MODIFICATEURS
    // ============================================================

    modifier onlyOwner() {
        require(msg.sender == owner, "Acces refuse : pas l'administrateur");
        _;
    }

    modifier diplomaExists(uint _id) {
        require(_id > 0 && _id <= diplomaCount, "Diplome introuvable");
        _;
    }

    // ============================================================
    //  CONSTRUCTEUR
    // ============================================================

    constructor() {
        owner = msg.sender;
        diplomaCount = 0;
    }

    // ============================================================
    //  FONCTIONS PRINCIPALES
    // ============================================================

    function issueDiploma(string memory _studentName, bytes32 _rawHash)
        public onlyOwner
    {
        require(bytes(_studentName).length > 0, "Nom obligatoire");
        require(_rawHash != bytes32(0), "Hash invalide");
        require(!hashUsed[_rawHash], "Hash deja enregistre");

        bytes32 internalKey = keccak256(abi.encodePacked(_rawHash, diplomaCount + 1));
        require(internalKey != bytes32(0), "Erreur de hachage interne");

        diplomaCount++;
        diplomas[diplomaCount] = Diploma({
            studentName: _studentName,
            diplomaHash: _rawHash,
            issuedAt:    block.timestamp,
            revoked:     false
        });
        hashUsed[_rawHash] = true;

        emit DiplomaIssued(diplomaCount, _studentName, _rawHash, block.timestamp);
    }

    function verifyDiploma(uint _id, bytes32 _hashCheck)
        public view diplomaExists(_id)
        returns (bool)
    {
        Diploma memory d = diplomas[_id];
        if (d.revoked)                   return false;
        if (d.diplomaHash != _hashCheck)  return false;
        return true;
    }

    function revokeDiploma(uint _id)
        public onlyOwner diplomaExists(_id)
    {
        require(!diplomas[_id].revoked, "Deja revoque");
        diplomas[_id].revoked = true;
        emit DiplomaRevoked(_id, diplomas[_id].studentName, block.timestamp);
    }

    // Bonus 1 — Récupérer les infos d'un diplôme
    function getDiploma(uint _id)
        public view diplomaExists(_id)
        returns (string memory, bytes32, uint, bool)
    {
        Diploma memory d = diplomas[_id];
        return (d.studentName, d.diplomaHash, d.issuedAt, d.revoked);
    }

    function getTotalDiplomas() public view returns (uint) {
        return diplomaCount;
    }
}

Questions d'analyse

1. Pourquoi le PDF n'est-il pas stocké directement sur la blockchain ?

Stocker un fichier PDF directement sur la blockchain coûterait des millions d'unités de gas car chaque octet stocké dans l'EVM nécessite environ 20 000 gas. Un PDF de 1 Mo représenterait un coût prohibitif (plusieurs dizaines d'ETH). De plus, la blockchain n'est pas conçue comme un système de fichiers : elle stocke des états de programme, pas des documents binaires.

2. Quel est l'intérêt de stocker uniquement un hash ?

Un hash (empreinte SHA-256) est une valeur de 32 octets qui représente de manière unique un fichier. Si le document est modifié d'un seul bit, son hash change complètement (effet avalanche). Stocker le hash garantit l'intégrité du document sans révéler son contenu, et pour un coût minimal (~85 000 gas). Toute tentative de falsification produit un hash différent, immédiatement détecté lors de la vérification.

3. La blockchain garantit-elle qu'un diplôme est "vrai" ?

Non, pas complètement. La blockchain garantit que le hash enregistré n'a pas été modifié depuis son émission (intégrité), mais elle ne peut pas vérifier que les informations initiales (nom, diplôme) étaient exactes au moment de l'enregistrement. Si l'administrateur enregistre un faux diplôme, la blockchain le stockera comme valide. La confiance repose donc sur la fiabilité de l'émetteur (l'université), pas uniquement sur la technologie.

4. Quel lien avec une PKI classique ?

Une PKI (Public Key Infrastructure) utilise des autorités de certification (CA) pour signer numériquement des documents. Le smart contract joue ici le rôle de la CA : seul l'owner (l'université = autorité de confiance) peut émettre ou révoquer des certificats. La liste des diplômes révoqués correspond à une CRL (Certificate Revocation List). La vérification publique du hash remplace la validation de signature numérique. La blockchain ajoute l'immuabilité et la décentralisation, absentes d'une PKI traditionnelle.

5. Problèmes de confidentialité si les données sont publiques

Si les noms des étudiants et leurs diplômes sont visibles publiquement sur la blockchain, plusieurs risques apparaissent : (1) violation du RGPD car les données personnelles (nom, diplôme) ne peuvent pas être supprimées — la blockchain est immuable ; (2) exposition professionnelle non souhaitée (un employeur peut voir l'historique complet) ; (3) corrélation d'identité avec d'autres données on-chain. Solution : ne stocker que le hash du diplôme sans le nom en clair, et utiliser un système de divulgation sélective (zero-knowledge proofs).

Bonus 3 — Calculer le hash SHA-256 d'un vrai PDF

Sous Windows (PowerShell) :
Get-FileHash C:\chemin\diplome.pdf -Algorithm SHA256

Sous Linux/Mac (terminal) :
sha256sum diplome.pdf

Le résultat (ex: a3f5c8...) est un hash hexadécimal de 64 caractères. Pour l'utiliser dans Remix, le préfixer avec 0x : 0xa3f5c8... et le passer comme paramètre bytes32 dans issueDiploma.

Conclusion

Ce TP a permis de développer un système complet de gestion de diplômes sur Ethereum. Le smart contract DiplomaRegistry répond à l'ensemble des exigences :

  • Contrôle d'accès via onlyOwner (seule l'université peut émettre/révoquer)
  • Stockage immuable des empreintes cryptographiques (bytes32)
  • Vérification publique et transparente sans révéler le contenu du diplôme
  • Mécanisme de révocation traçable via les événements DiplomaRevoked
  • Anti-doublon de hash (Bonus 2) pour éviter les enregistrements frauduleux
  • Utilisation de keccak256, struct, mapping, modifier, event, constructor, require

La solution démontre comment la blockchain peut remplacer une base de données centralisée pour la certification de documents, tout en offrant transparence, intégrité et résistance à la falsification.
